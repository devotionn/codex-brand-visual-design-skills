# 团队使用说明｜给品牌 / 平面 / 视觉设计师

这套仓库不是前端 UI Skill。它面向 Logo、VI、公司画册、产品效果图、KV、海报、品牌视觉、AI 图片辅助和印刷交付。

## 设计师平时只记一个入口

```text
$brand-design
```

Codex 会根据任务继续使用更具体的能力。你不需要先研究所有 Skill。

## 例 1：Logo / VI

```text
$brand-design
这是一个新的酒店用品品牌。附件里有公司介绍、老板给的几个参考 Logo 和现有产品照片。
先帮我整理品牌设计 Brief，再给 3 个明显不同的 Logo / VI 创意方向。
不要只换颜色或字体，要解释每个方向的识别逻辑、图形语言、字体方向、颜色和适用场景。
```

## 例 2：公司画册

```text
$brand-design
帮我规划一本 24P 公司画册。
先检查我给你的公司资料和图片，把内容分层，给出逐页 Page Map，再建立封面、目录、章节页、企业介绍、产品页、案例页和结尾页的统一版式系统。
如果文案或图片不够，明确标记缺口，不要自己编公司事实。
```

## 例 3：效果图 / KV

```text
$brand-design
我要做一张酒店布草产品的主视觉，横版 16:9，用于展会大屏。
希望高级但不要传统黑金风。先给 3 个 Art Direction，再把选中的方向拆成构图、场景、镜头、光线、材质、色彩、产品位置、文案安全区和 AI 出图 Prompt。
```

## 例 4：审稿

```text
$visual-review
这是我刚做的画册封面和 4 个内页。
不要只说好不好看。请从品牌感、信息层级、构图、字体、颜色、图片、统一性、商业感和印刷风险逐项检查，按优先级告诉我先改什么。
```

## 例 5：印刷前检查

```text
$print-production
这是准备交印厂的画册文件和印厂要求。
帮我按印厂要求检查尺寸、出血、安全边距、图片分辨率、色彩模式、黑色、字体、透明效果、装订和导出风险。
没有实际检查到的项目不要写 PASS。
```

## 怎么给 Codex 素材

最好同时提供：真实 Brief、现有 Logo/VI、文字资料、产品图、参考图、成品尺寸、应用场景、印刷厂要求，以及你自己认为“绝对不能变”的内容。

如果资料不全，也可以先做。Codex 应该只追问会实质影响方向的问题，其余用明确假设推进。

## 人和 Codex 的分工

Codex 适合做：资料梳理、方向发散、参考拆解、版式系统、Prompt、批量检查、修改清单、交付检查、可复用规范。

设计师继续负责：最终审美判断、品牌取舍、创意选择、细节打磨、图片精选与修图、字体与版权确认、客户沟通、打样和最终签字。

## 迭代方法

不要先花一天学习这套仓库。直接找一个真实任务使用 `$brand-design`。把不好用的地方、错误判断、常见返工原因和你自己的设计标准记录下来，再持续写回 Skill。这样它才会逐渐变成公司自己的设计工作流，而不是一套通用提示词。
